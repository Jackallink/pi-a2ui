## P1 observations reproduced before repair

1. **Chart-only publication exceeds256KiB through sequence growth.** Construct a legal snapshot with Chart+Text, dataSequence9, and an ASCII Text filler so JSON.stringify(snapshot) is exactly262144 bytes. Reset and updateChart with the identical valid series succeed. After the scheduled publication, dataSequence becomes10 and the snapshot becomes262145 bytes. checkCapacity reserves counter headroom only when LogView exists, while flushData increments a Chart-only sequence afterward. All live-component states require counter-growth headroom or an equivalent atomic post-increment capacity proof.

2. **Restore admits more than the global encoded log budget.** Construct two valid LogView surfaces and set each saved text to40000 ASCII characters. reset succeeds, yielding80004 combined JSON-encoded text bytes. Per-view validation enforces only the65536 individual bound; checkCapacity strips log text for reserve arithmetic without first enforcing global encoded sum/equal share. The canonical contract specifies a global65536 budget shared across current views. Enforce it before committing restore, including non-log updates or adding views that would invalidate an existing share. Failure must preserve state and pending publication.

3. **Old cumulative prefixes replay once per-tool trimming has begun.** Start a current-run native tool and deliver1500 lines row0..row1499 (less than64KiB). Then deliver an older100-line cumulative prefix row0..row99. Independent fake-session observation showed the visible tail change from row1499 to row99 and appended `[output snapshot replaced]`, instead of ignoring the stale prefix. snapshot() applies the ring's1000-line trim to the retained per-tool window, so previous.length no longer equals previous.tail.length and the old-prefix branch cannot recognize this case. The per-tool window budget and visible ring line budget are separate. Shorter recognized stale snapshots must also leave the retained high-water window unchanged, otherwise an A→AB→A→AB sequence duplicates B. Large/truncated windows require a rule based on observable cumulative overlap/native truncation metadata; do not claim an unknowable prefix match after discarding its evidence.

These were reported immediately with concrete Node probes. The implementer acknowledged the first two and began regression-first repairs; no post-repair pass is claimed by this preliminary record. Final independent review must inspect the final code and regressions, plus the separate browser/native-tool/package/GLM evidence.

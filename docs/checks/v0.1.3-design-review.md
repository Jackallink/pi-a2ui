## Decision

No P0/P1 design blocker identified. The proposed design remains bounded and avoids a second execution/runtime platform: native tool events feed a small current-run adapter and bounded ring; current UI session owns one coalescing timer/latest-per-surface queue; existing authenticated SSE carries live-only component updates; SDK updateComponents preserves form/layout identity; chart mutation stays inside a guarded Pi UI tool. Live data sequence does not replace structural revision as action authority.

The64KiB JSON-encoded global log budget,1000-line cap,32 active tool identities with bounded cumulative snapshots, at most4 pending surface payloads and at most10 data batches/sec provide explicit resource boundaries. Structural admission reserves aggregate log headroom plus1024 bytes under the inherited256KiB snapshot ceiling. Aggregate JSON entry/collection/depth/component/client/backpressure ceilings remain binding; these are joint limits rather than promises that every per-widget maximum fits simultaneously.

Recovering gaps by opening a new SSE stream and applying its authoritative initial snapshot avoids an independent HTTP snapshot racing a newer event stream. Ignoring callbacks from superseded EventSource instances, wrong epoch/revision and old/duplicate sequence preserves coherent recovery. A same-revision snapshot patches live models only, preserving browser-local input drafts and structural event authority.

Native current-run admission/termination, exclusion of a2ui_* tools, dropping queued updates on structural replacement, invalidating run ownership on pause/session/tree/reset/exit, and restoring running logs as interrupted close the lifecycle path. Old log events are not replayed from persisted history. Chart tool snapshots can be authorized restore records without treating arbitrary messages as state authority.

## Required implementation counterexamples / precise interpretations

These follow from the existing contract and must be exercised at code review:

- Log headroom remains reserved on every mutation that can increase non-log payload, including chart updates and restoration, not merely initial a2ui_render. Test control characters whose JSON escaping expands byte size; multi-view redistribution; an almost-full structural snapshot; and failures leaving both state and queued patch unchanged. The ring and per-tool cumulative snapshots need code-point-safe truncation so split/unicode updates do not invent or lose the newest suffix.
- Rate/sequence tests must distinguish server committed state from pending publication. A reconnect snapshot while a batch is pending must not allow rollback or lose a subsequent batch. Replacement/reset must discard old queued patches; sequence must be bounded safe-integer state; listeners/timers must release on close and cancellation. A stopped-reading client must remain subject to the existing bounded SSE queue policy.
- Cumulative tool output is not a delta. Duplicate and older prefixes do not append; changed/truncated windows require an explicit marker, and storing only a bounded last window must not make a later repeated cumulative snapshot append twice. Test32-active admission, unknown IDs, failed/silent tools and late end/update after run invalidation.
- Pi1.5 agent_end exposes messages, not an outcome field. Terminal state must distinguish completed/aborted/error from actual native evidence (e.g. final assistant stopReason and agent_settled.aborted where used); do not show an aborted/error run as successful completion simply because agent_end fired. Collection must still end at the specified ownership boundary.
- Extreme finite chart values need normalization before arithmetic that could overflow; verify rendered SVG coordinates remain finite and accessible table values remain exact. Preserve series-name uniqueness, identical label order, <=4 series/<=200 points, and reject unknown executable options. Empty/zero/negative/mixed-sign series need literal oracles.
- Live update admission cannot modify component kind/layout/IDs, current Button declarations, CodeDiff/TestResults identity data or input data-model values. The chart tool captures current operation/cancellation state and rejects stale revision/component; event actions remain governed by epoch+structural revision while dataSequence advances.
- Actual browser checks must verify input DOM identity/draft, local pause text and selection, follow-vs-scrolled behavior, gap reconnection and stale-source suppression. L-07 needs actual native timed output and actual chart-tool update through a production-installed package, plus the same-session GLM acknowledgement and cleanup; inherited TextField-only acceptance is insufficient.

## SDK/test evidence

Installed Pi extension types expose agent_start, agent_end.messages and tool_execution_start/update/end with toolCallId/toolName, partialResult or final result/isError. Installed bash.js emits output.snapshot(...).content as partialResult text, confirming the cumulative snapshot adapter premise. Tool event ownership is a plugin lifecycle contract, not something to infer from arbitrary output text.

The six initial tests/live.test.ts cases use existing compiler/session entrypoints: positive live-catalog compilation establishes behavioral RED on the predecessor; subsequent tests cover finite/aligned chart data, log truncation, coalescing/structural action authority, stale lifecycle operations and guarded chart persistence.

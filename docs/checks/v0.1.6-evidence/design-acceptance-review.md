## P1 — model profile isolation does not yet close the owned-working-directory boundary

Locations: spec011:25,29,31–39; Plan011:48–53; Round1 AC-006/007/008 at lines24–26; Round2 P-004 at line19.

Startup explicitly owns its private project/agent directory (spec:29), and component mode explicitly gets a NEW owned cwd (spec:37). Skill mode instead says explicit isolated package/skill profile and gives `--no-extensions -e PACKAGE --no-skills --skill PACKAGE/skills/pi-a2ui` (spec:31). Those flags isolate resource loading, **not the process/model-tool working directory**. The skill story requires model adaptation and helper preflight, which can create temporary Express sources. Without a common cwd/path invariant, an implementation can satisfy the described skill profile while writing those sources into the operator's actual project. The existing worker uses `cwd:process.cwd()` (`scripts/live-acceptance.mjs:32-34`), so simply moving that worker structure is a concrete route to the gap.

Changing cwd alone is insufficient for the legacy worker: it reads an absolute-capable `A2UI_ACCEPT_WORKSPACE` and creates its output/fixtures there (`scripts/live-acceptance.mjs:14-31`). Ambient `A2UI_ACCEPT_SCENARIO`, `A2UI_ACCEPT_RESTORE_ONLY` and `A2UI_ACCEPT_PROVIDER_EXTENSION` can also change the worker's observed scenario/profile/extensions unless the new admitted entry owns those inputs. An unchecked absolute workspace can bypass the new-run ownership guarantee even when Pi starts from a private cwd.

**Smallest correction before Gate1 GO:**

1. Freeze one common invariant: after admission, all three modes create a new private owned run; Pi/model/bash/helper temporary source and fixture writes use that owned cwd. The explicit package is a read-only target. Neither original operator cwd nor the package tree is a model/work-file destination.
2. The validated entry controls mode/scenario/run/package/model tuple and passed worker environment. Legacy environment values cannot override them or inject an unadmitted provider extension/profile. Reject/ignore old values or internally replace them with the validated owned inputs; do not add a new public test-injection/config surface. Keep the five admitted supplied-DSL component scenarios; clarify that an unexposed restore-only environment path cannot silently substitute another evidence tier.
3. Add AC/test intent proving the child's real cwd and successful/failing/timeout paths leave operator/package sentinels or hashes unchanged, including a hostile absolute legacy workspace override. Keep cleanup restricted to owned registration/run/child resources. Actual user credentials remain read-only for the explicitly opted-in model tier; do not copy them into the fixture.

Root agreed this P1 during review and will correct it in a new pinned R2. This report intentionally preserves the original8f7e975 NO-GO rather than reviewing uncommitted successor wording.

## Sound portions of the reviewed design

- **Explicit target and early guard:** spec:25–27 requires absolute package path and exact expected version, disallows positional/default old010 fallback, asserts actual Node major24 before SDK/browser workers or fixture creation, checks package/helper/files/dependencies before Pi work, and records actual identities. Pure version-string tests under Node24 avoid running an unsupported Node22 process. Existing baseline166/166 and structural walkthrough validation are historical/setup evidence, not validation of these new behaviors.
- **Default no inference:** startup is the default, rejects unnecessary --allow-model, uses private dummy model metadata plus external-fetch denial, invokes only status and requires0agent_start. Model modes cannot run without --allow-model. Wrong/missing/extra flags, version mismatch and absent consent stop before Pi/browser/fixtures. A01 helper lookup remains read-only rather than becoming a rendering or execution CLI.
- **Normal registration versus explicit model profile:** startup uses real project-local Pi install with no -e/--skill overrides, requires exactly one skill and correct sourceInfo. The installed Pi SDK does expose get_commands.sourceInfo and resource path/source/scope/origin metadata, so this is an implementable source check, not a guessed host field. Skill mode deliberately uses explicit overrides to avoid the user's installed015 and is not mislabeled as normal-registration evidence. These are separate receipts, not a substitution of one tier for the other.
- **Model gate:** spec:31–33 requires get_state.success plus exact actual provider/id/baseUrl before any prompt; environment cannot widen the existing Ark AgentPlan tuple. No fallback/retry or new model/account is introduced. The bounded story supplies requirements, not DSL, and actual helper preflight/render plus invalid0POST/valid1POST/Ada-true typed acknowledgement is required. Known-template usage need not make an artificial patterns/reference tour or manufacture native-timeline evidence.
- **Prior harness failure lessons are addressed directly:** spec:35/39 requires public SDK component-ID/native-control adaptation rather than tag/index/accessible-name guesses, actual feedback rather than invented alert roles, pageerror persistence before metadata extraction, Array.isArray content normalization, per-stage durable outcomes and strict cleanup gating. Reports preserve earlier observed stages and separately classify setup/model/transport/browser/parser failures. Bootstrap/cookie/auth/raw RPC are excluded from the small stdout summary; private run/log permissions are explicit.
- **Existing component scenarios are retained honestly:** spec:37 and AC-008 preserve basic/forms/coding/live/workbench supplied-DSL behavior, separately label suppliedDsl=true/skillForward=false and reject unknown scenarios instead of silently selecting basic. They cannot be counted as model-authored skill evidence. Their exact worker environment/cwd must receive the P1 correction above.
- **A03 scope and authorization remain bounded:** spec:43–45 keeps progressive task→example→adapt→check→tool routing and all32 types/19 examples/8 patterns, allows a deliberate016 candidate version preparation, and leaves published Git guidance/user-global015/old tags/assets untouched. No new UI/catalog/server/RPC/dependency/doctor, automatic upgrade/uninstall, npm publication,016 merge/tag/release or real-user installation replacement is authorized. One actual model case cannot establish a general cost/success-rate improvement.

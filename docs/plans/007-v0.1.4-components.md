# v0.1.4 component delivery plan

> Planning-only. Implementation begins per issue only after its strict spec/walkthrough/TDD admission and user authorization; use executing-plans for the admitted slice. Do not restart the stopped Pi worker or infer permission to build/publish from this file.

**Goal:** 完整覆盖C01–C14七组日常交互能力，提升Pi阅读/比较/输入/状态/产物检查体验。

**Architecture:** 沿用显式a2ui_render、共享schema、受限catalog、Lit实现、epoch/revision事件和有界SSE数据更新。新媒体通过单独受审的会话产物能力进入，不能变成任意文件服务。CopyAction/组合部件优先复用现有机制。

**Tech stack:** Node24.x only、Pi1.5当前基线、锁定A2UI SDK、TypeScript/Lit、node:test/Playwright；模型验收仅AgentPlan GLM。

**Spec:** ../specs/007-v0.1.4-usability.md（唯一范围）；walkthrough: ../walkthrough/v0.1.4/walkthrough.md。

## 范围/依赖/实施顺序

版本总范围是七组，不把分批当成七个版本。阶段A：W1/W2/W3，先解决读结果、读代码、长内容。阶段B：W4/W5，真实状态及聚焦详情；W4延续现有native/live生命周期，W5依赖完整slot遍历。阶段C：W6先关闭D1–D4并交付产物/Image，再由W7复用其能力交付Video/AudioPlayer。各组设计可提前推进，资源实现不能越过门禁。

## 最终版本入场

全部C01–C14及RLS-01–04通过才准备0.1.4发布；未覆盖项保留阻断，只有用户明确变更范围才可调整。单组完成不授权发布或关闭整个版本。当前package/.nvmrc/发行物仍是已发布0.1.3，不为“规划完成”提前升版本。

R01–R08单独候选issue先评估是否已有组件组合即可解决；未明确纳入前不增加必须实现的catalog类型、依赖或API。

## 风险与回退

媒体源/权限/缓存清理是strict高风险，需独立证据；键盘/Markdown/复制也应有真实浏览器边界。回退只切换本包注册并回收本包拥有资源，保留用户文件/凭据；回退到0.1.3可能跳过新组件快照。

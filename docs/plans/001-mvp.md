# Pi A2UI MVP implementation plan

For agentic workers: implement task by task with TDD and independent review. User authorized continuing after review GO; no additional execution-choice prompt is needed.

Goal: ship an installable local Pi tool-to-browser interaction loop.
Architecture: explicit Pi tool, official SDK compilation, atomic session, native HTTP SSE/POST, bundled Lit client.
Tech: Node >=22.19, TypeScript, node:test/tsx, esbuild, pinned A2UI SDK, Pi >=1.5.
Spec: ../specs/001-pi-a2ui-mvp.md . All spec limits and authorization boundaries apply verbatim.

## Task 1: compiler and atomic session

Files: package.json, tsconfig.json, src/compiler.ts, src/session.ts, tests/session.test.ts.
Interfaces: compile(surfaceId,source) -> validated complete createSurface; UiSession.render(...) -> snapshot; acceptAction(envelope) -> accepted/duplicate or typed error; reset/restore.

- Write behavior test with a temporary empty-session implementation: render valid Card/Text fixture and assert independently expected visible text and revision. Run node:test through tsx, confirm assertion RED (not import/compile failure).
- Implement official SDK compilation, restricted catalog, complete-state materialization and atomic commit. Confirm GREEN.
- Add RED cases for invalid/extra surfaces, limits, cancellation, event context (literal tampering, missing/extra keys, string TextField bindings only), stale epoch/revision, duplicate/conflicting IDs, disabled and dispatch throw. Implement minimally and confirm GREEN.
- Test depth=16 boundaries, immutable snapshot ownership and listener failure isolation. Test restoration with valid/failed/malformed/oversize snapshots and current epoch isolation. Persist only snapshots.

Example oracle: `root = Card(Text("Ready"))` must commit a Text node containing literal Ready; `root = UnknownWidget()` must leave the prior revision/text intact. Action fixture declares submit and a bound field; acceptance must contain the submitted field and send once.

## Task 2: HTTP boundary and browser

Files: src/server.ts, src/client.ts, src/client.css, scripts/build.mjs, tests/server.test.ts.
Interfaces: startServer(session) -> origin/openUrl/close; browser bootstrap/connect, events snapshot and actions envelope per spec.

- Write native HTTP tests against an initially denying server to observe valid bootstrap/SSE/action assertion RED. Implement host/origin/cookie boundaries, bounded JSON, routes and close.
- Add behavior RED for unauthorized data/actions, foreign origin/Host, stale action, body limit, client cap, close with active SSE. Confirm minimal fixes GREEN.
- Build official Lit renderer against the same restricted catalog; snapshot reconciliation preserves unchanged revision nodes. Keep draft input in SDK state. Show connected/submitting/accepted/rejected/uncertain delivery statuses. Clear fragment and never log credentials.
- Bundle JS/CSS with esbuild. Exercise real browser card/form, invalid source preservation, another-surface update, refresh/reconnect and action/error feedback.

Example HTTP oracle: no cookie GET /api/events ->401; correct bootstrap ->cookie; authenticated events contain Ready; foreign Origin POST ->403 and zero delivered messages.

## Task 3: Pi integration, package, review and local acceptance

Files: extension.ts, tests/extension.test.ts, README.md, package.json files/pi metadata, docs/checks/*.
Interfaces: default ExtensionAPI initializer registers a2ui_render/commands; bridge sends structured data with followUp; branch restore is pure and validated; shutdown closes server.

- Write failing restore/integration behavior tests using minimal bridge doubles only at Pi process boundary. Include deferred lazy startup then reset/close/disable; old generation must not commit and late startup must close. A void bridge returning then failing asynchronously does not become confirmed Pi delivery; test exactly one local invocation, and observe real next-turn continuation separately. Compile against Pi 1.5 types. Implement hooks and concise tool results, SDK prompt rules, lazy service and platform browser opening.
- Build, typecheck, run focused/full relevant tests, npm pack and inspect/install archive in a temporary consumer. No user build allowed.
- Independent reviewer audits final diff, authorization, parser/auth/resources/history/input behavior and tests. Fix P0/P1 and re-review.
- Install validated local archive/package with pi install path, preserve other settings; run a bounded real model/tool/browser form -> action -> next turn. Verify shutdown/reload; uninstall/restore registration if acceptance fails. Record observed evidence and any live blockers. Public publish is excluded.

Rollback is spec-defined. Checks and execution status live in docs/checks, not this plan.

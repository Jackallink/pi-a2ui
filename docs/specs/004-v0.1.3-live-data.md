# 0.1.3 — Live logs and charts

Lifecycle: draft. Profile: strict. Scope approved for iteration planning on2026-11-13; implementation admission requires the version-specific walkthrough/TDD gates. Dependency:0.1.2.

## User outcome and scope

Users can follow bounded tool output and inspect structured result trends while retaining control of the same Pi task.

IN: LogView fed by Pi tool execution/output events, bounded incremental updates, sequence/gap handling and snapshot recovery; a Chart component for basic line/bar series with a constrained data schema; preserved browser scroll/selection where appropriate; paused/disconnected/error/end states.

OUT: remote telemetry services, unlimited log retention, terminal emulation or commands executed from log text, arbitrary chart JavaScript/options callbacks, new model calls per log chunk, automatic operational remediation or remote hosting.

## User stories and acceptance criteria

| ID | Story / Given-When-Then acceptance |
| --- | --- |
| L-01 | Given an authorized current-session tool stream, when output arrives, then LogView receives ordered bounded updates without an extra model call per chunk. |
| L-02 | Given logs exceed1000 lines or64KiB per view, when appended, then the older portion is bounded and the UI visibly indicates omitted earlier content; total snapshot remains within256KiB. |
| L-03 | Given a paused/slow/disconnected client or sequence gap, when updates resume, then it recovers a coherent bounded snapshot; memory/queues stay bounded and scroll behavior is deterministic. |
| L-04 | Given line/bar chart data, when rendered/updated, then finite points/labels and series mapping match input; reject over4 series, over200 points per series, malformed/nonfinite values and executable options. |
| L-05 | Given cancellation, tool end, session/tree change, reload or exit, when lifecycle changes, then old streams cannot update the new session and subscriptions/timers/listeners are released. |
| L-06 | Given another surface with unsent input, when log/chart data changes at up to10 published batches/second, then input, action authority and structural component identity remain coherent. |
| L-07 | Given built0.1.3 and glm-5.3-flash, when Pi opens an execution canvas and tools emit real output, then browser progress/end/results are observed and a selected next action returns to the same conversation. |

## Technical design and test intent

Add explicit data updates to the current atomic-layout session model. Distinguish structural revision/action admission from live data sequence; document exactly when actions become stale. Use deterministic tool-event collection and a bounded ring buffer/coalescing path. The recovered LogView payload uses bounded text rather than a1000-element JSON collection; chart series are capped at200 points each, below the inherited256-entry collection limit. Aggregate4096-node/256KiB snapshot limits still apply. The model defines the layout and interprets results rather than regenerating a surface for every log line. Unsubscribe by owning tool/session lifecycle.

Keep SSE/POST transport and existing authentication boundary. Snapshot recovery is authoritative after gaps; never turn missed log chunks into unbounded server history. Chart rendering uses local packaged code and a constrained series/axis/data contract, without evaluating model-supplied script or fetching arbitrary resources.

Map L-01/02 to native event/buffer tests with independent order/truncation oracles; L-03/05 to reconnect/backpressure/cancel/cleanup tests; L-04 to chart schema and actual renderer tests; L-06 to concurrent input/data/revision browser cases; L-07 to real Pi/tool/browser/GLM acceptance. Include split/unicode chunks, duplicate/out-of-order notification, silent/failed tools, initial empty chart and a client that stops reading.

## Risk and rollback

Incremental data crosses lifecycle/resource boundaries; require strict review before code. Current published snapshot/client/action limits remain binding unless a reviewed spec explicitly changes them. Proposed line/point/rate limits above are iteration acceptance targets, not0.1.0 capabilities. Rollback stops subscriptions and returns to the0.1.2 package; it does not delete Pi history or require credential changes.

## Goal, scope and alternatives

Pi users can navigate small hierarchies, select from long lists, read concise summaries, fix field errors, distinguish empty/loading/error states, inspect actual tool order, cite source locations and find current actions by keyboard. Every group includes a discoverable skill route and executable helper template. Node **24.x only**, host Pi >=1.5.0. Actual inference, when admitted, uses only the existing **Volcengine Ark AgentPlan glm-5.3-flash**, endpoint `https://ark.cn-beijing.volces.com/api/plan/v3`, with model/provider/endpoint preflight and no fallback.

Recommended architecture: composition first, three new catalog APIs for demonstrated gaps, plus browser-local command palette. Alternatives considered: (A) add a separate public type for every marketing name, increasing schema/prompt/maintenance without functional gain; (B) templates only, which cannot supply actual searchable selection, server-enforced constraints or a native event timeline. Recommended (C) combines existing layouts with three narrowly scoped APIs. No new dependencies, execution CLI, model provider, generic RPC, arbitrary filesystem browser, outside links, validation functions/checks, remote code, virtualized IDE tree, unlimited history, npm publication or user installation. Existing auth/resource/action budgets remain unchanged.

## Public data contracts

New `interactions-v1` catalog ID: `https://jackallink.github.io/pi-a2ui/catalogs/interactions-v1.json`. Preserve all four existing catalog IDs and their existing schemas. Compiler authoring selects interactions-v1; restore recognizes all previous catalogs. Exactly 29 existing + **3 new types = 32**; pattern names are never counted as APIs. Browser and helper use the same schema source.

**SearchablePicker**: `label` literal string 1–128; `options` static array 0–200 of strict `{label:string(1..128),value:string(1..128)}` with distinct values; `value` required absolute initialized string-array binding (same binding schema as ChoicePicker); `variant` enum mutuallyExclusive/multipleSelection, default mutuallyExclusive. Options/label/variant cannot be bindings. Query local, bounded to128 Unicode code points, case-insensitive substring match of labels, no regex/network. Duplicate labels allowed, IDs unique. Selection must remain a subset of options; single mode <=1; no free-text submitted values. Empty options are legitimate and display “No options”; unmatched query displays “No matches”. Clearing/removing values is explicit. Filtering never changes selection or data model; hidden selected values remain visible as selected chips/removal controls. Native buttons/checkboxes with accessible labels; query input plus listbox/options or native selection controls follow the implementation's actual semantics, not a false combobox role. Arrow Up/Down moves active result, Home/End jump, Enter/Space selects from the result list, Escape clears/closes the query panel without submitting, Tab exits. Multiple mode never selects a query string. Reconnect/data-only updates preserve local query/selection; full replacement resets them. Extend inputPaths/validateInput/validateInputs and bound context checks for this type.

**FormValidation**: `title` literal string 1–128, default “Check these fields”; `buttons` static distinct component IDs 1–16; `rules` static array1–16 of strict `{fieldId:string(1..128),message:string(1..256),required?:boolean,minLength?:int(0..4096),maxLength?:int(0..4096)}`. Defaults required=false; at least one meaningful check per rule; min<=max. At most one FormValidation per surface. Each fieldId names one reachable TextField/CheckBox/ChoicePicker/SearchablePicker/Slider/DateTimeInput, with an initialized absolute value binding. Duplicate field IDs or rules for shared input paths are rejected. Each guarded button names a reachable Button whose declared event binds **every rule's input path** in its context. Constants, omitted fields, nested bindings or targets outside this surface do not satisfy coverage; malformed validation declarations fail render atomically, not silently.

Required: TextField/DateTimeInput must contain a non-whitespace string; CheckBox must be true; choices must have >=1 selected; Slider must have a valid finite number (existing range checks apply). minLength/maxLength apply only to TextField (Unicode code points, raw submitted value) and choice arrays (selection count), not checkbox/slider/date; incompatible rules fail compile. Business-invalid initial drafts remain renderable, unlike structurally invalid input types/options/ranges. Existing typed validation always runs, then these constraints on guarded submit. Non-guarded navigation/cancel buttons retain existing behavior. Error response uses existing403/message surface, no new API/envelope; no dispatch or event-ID consumption on invalid data. Client and server import one pure evaluator with deterministic field-order messages; DOM and server authority stay separate. Browser displays summary at FormValidation and adjacent per-field messages, aria-invalid/aria-describedby, focuses first failing field, opens containing Details/Tabs if needed or focuses the visible summary if the field cannot be shown. Revalidation after edits clears resolved errors without a POST or model turn; invalid submit performs no POST. Labels/messages remain escaped text. Never include submitted values in error messages. New epoch/revision removes old errors. No async validation, model checks, arbitrary regex, executable functions or automatic retries.

**ActivityTimeline**: `stream` literal tools default; server-controlled `entries` default [], `state` existing idle/running/completed/error/paused/interrupted default idle, `omitted` boolean default false. Entry: strict `{id:string(1..128),name:string(1..64),state:running/completed/error/interrupted,startedAt:nonnegative safe integer epoch ms,elapsedMs:nonnegative safe integer}`. <=32 retained entries **per run**; drop oldest rows, set omitted, never fabricate missing entries. At most1 timeline per surface. Model cannot initialize entries/non-idle state/omitted=true. Timing comes from real tool start/end events; clamp negative elapsed caused by clock changes to0; running duration is a last-observed value, visibly labelled, not a continuously ticking guarantee. Native a2ui_* tools excluded as in TaskProgress. Duplicate starts/ends do not duplicate/flip outcomes. Only tracked active tools (existing32 cap) get rows; tool-ID seen cap1024 and omissions remain explicit. beginRun clears previous timeline; finish/error/cancel marks outstanding running rows interrupted, while completed/error records remain truthful. No tool arguments/output/path/credentials copied into timeline. Restored running rows become interrupted; pause converts running rows to interrupted and sets container paused; resume begins an empty idle timeline and cannot reattach old operation ownership. close/reset prevents late events. Late rendering is hydrated by LiveTools.refresh, even if tools started before UI existed. Include timeline in data-only filters, sequence/headroom/reserved capacity checks, reset/pause handling and client mounted live-ID validation; native patches must not change layout or input drafts. Reserve **16KiB per timeline surface** in snapshot capacity (four surfaces <=64KiB) in addition to existing global log reserve; fail initial render atomically when headroom cannot fit. Timeline update cannot exhaust space reserved by already-admitted layout.

## Browser adapters and palette

The pinned SDK0.15.0 renders light DOM elements with `context.componentModel.id` and a resolved `node`, and input controller setters. Do not depend on generated tag suffixes or DOM positions. Add one browser adapter confined to a mounted A2uiSurface: find host by component ID, traverse shadow roots for actual focusable controls, and keep source IDs from the current snapshot. Missing/unsupported host fails closed and gives summary/empty state; never synthesize an execution action from a label. Browser tests must prove the adapter against the installed SDK, including no positional input assumptions.

Palette dialog derives candidates fresh from declared Button components in current mounted surfaces (max64 total) and currently connected, rendered, enabled, visible native action controls, excluding hidden Details/Tabs/closed Modal content, local copy/modal/media controls and controls beneath inert ancestors. Label from escaped rendered text <=128; duplicate labels disambiguated with surface ID and source ID. Opening with button or Ctrl/Cmd+K in canvas (not in another modal, not while paused/pending) stores epoch+revision+source ID, not draft context or action payload. Query <=128, local substring search; Up/Down/Home/End, Enter choose, Escape cancel and focus return, Tab stays in modal. Before choose, close dialog, resolve same epoch/revision/source ID again, require current availability, then invoke that Button's **actual current control click**; SDK resolves current draft context and existing sendAction handles validation/pending/envelope. No direct new POST path and no copied payload. Any revision/epoch/availability change while open closes/invalidate candidates; data-only updates preserve form state. Expired/stale targets give a visible refresh notice and no dispatch. Repeated Enter while an action is pending cannot queue another action. Restore and BFCache re-evaluate availability. Palette is local shell capability; `pattern command-actions` generates declared actionbar buttons and explains the shell shortcut, never an invented component call.

## Skill/CLI delivery and capability identities

Add references `navigation-and-selection.md` (R01/R02), `summaries-and-feedback.md` (R03/R04/R05), `timeline-and-evidence.md` (R06/R07), `keyboard-actions.md` (R08). SKILL.md routes by task; full signatures/limits live once in those references. Eight new templates: `tree-navigation`, `searchable-picker`, `summary-metrics`, `validated-form`, `feedback-states`, `activity-timeline`, `evidence-location`, `command-actions`; total19 with existing11. Templates state fixture/reported data vs actual native events. Source IDs/rules target explicitly named variables, not auto-generated compiler IDs. R01/R03/R05/R07/R08 templates use actual existing APIs; never falsely gate them on hypothetical types.

Extend allowlisted manifest entries with optional `pattern` and `reference`; `patterns` returns exactly eight groups, template, reference, required components, available flag and local package/catalog identity. `pattern NAME` returns the allowlisted group's same JSON descriptor (not a dynamically resolved path); unknown/extra arguments exit2 or1 consistent with existing command semantics (unknown command/arity2, unknown named item1). Existing example NAME remains raw source; check still returns exact a2ui_render arguments. No script executes actions, renders, auto-opens, calls inference or reads files outside explicit check input/packaged resources. An old helper lacking patterns reports usage, not a successful supported capability. `catalog` describes only the installed helper package; active tool wins when a different extension version is loaded. Templates are compiled by the exact installed compiler before output. Entry and references must distinguish catalog type, composition pattern, native lifecycle and local shell action. No automatic cross-version migration or automatic plugin upgrade.

## Risks, compatibility and rollback

New field constraints affect only explicitly guarded buttons on new interactions catalog; old schemas/actions remain unchanged. R01 hierarchy uses the existing component64/depth16/source32KiB budgets; examples cannot claim an unlimited filesystem navigator. Eight pattern labels are not new SDK components. Browser DOM adapter and native timeline capacity are the main integration risks and require actual browser/budget tests before acceptance. A2UI native elapsed/order are observed evidence; caller-supplied summary/evidence locations are reported references until Pi independently inspects them. A browser request is intent, not permission to execute/read a path.

Restore v0.1.4 snapshots unchanged under their old catalogs. Restore compatible v0.1.5 timelines as interrupted, never re-read artifacts. Downgrading to0.1.4 may reject/skip unsupported interactions-v1 snapshots using the existing latest-compatible restoration behavior; verify with a real old package, preserving original session files. Rollback removes the candidate in the same registration scope and restores immutable v0.1.4; no original session/config/credentials deletion. Source rollback reverts per-issue commits and rebuilds dist. Record actual drift only when observed; no product implementation drift exists in this design-only revision.

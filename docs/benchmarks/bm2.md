# BM2 golden scenarios

Use Node24.x (`nvm use 24`) and the lockfile (`npm ci`). This is a maintainer benchmark, excluded from the installed Pi package. It starts no Pi agent or model and reads no user model/auth configuration.

`npm test` runs the existing suite plus61 registered compiler/session cases and separate checker canaries. `npm run check` checks types. Install the locked test browser with `node node_modules/playwright/cli.js install chromium-headless-shell`; on Linux CI use `--with-deps` as in the workflow. `node tests/golden/run-browser.mjs` runs the existing browser regressions plus7 registered browser cases and an additional real aborted-request canary, with a5minute runner limit. An explicit `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` must point to the exact locked browser version; an older cached binary cannot produce a complete receipt.

Raw local reports are ignored under `.local/golden-reports/`. After both layers pass on the same **clean committed source**, run `node --import tsx tests/golden/report-cli.ts combine-local`. The fixed combiner rejects missing/duplicate/not-run/failed rows, wrong per-case input hashes, dirty source and incompatible source/profile/lock/catalog/assets/dataset/oracle fingerprints. Node-only success leaves7 browser cases unrun. Separate GitHub jobs export bounded receipt metadata through job outputs; a third job verifies the exact compatible61+7 union against its current checkout. No model/provider secrets or action context are exported.

Cases are explicit in `tests/golden/cases.json`, with the separately frozen identity matrix and complete Express/JSON/media fixtures. Compiler cases cover32 supported component contracts and14 intended rejection contracts. Product legality comes from the real compiler and actual shipped helper CLI; handwritten expected values test the declared intent. Session cases use actual UiSession/server/artifact paths, and browser cases use real renderer actions and HTTP202 plus typed callback observations. A compiler pass alone does not prove intent, interaction, geometry or real Pi/model execution.

Expected product rejection can pass a negative case only with a valid control and the specified reason/status/known location. Setup, missing fixture, unknown exception, cancellation, transport or cleanup failure cannot count as a passing negative. Canaries are outside the68 registered scenarios. There is no automatic retry, expected-output capture or baseline update command.

For changes, update Spec016 and the fixed matrix/inputs/independent expected invariants before implementation; obtain the independent TDD review, preserve meaningful RED and original failures, and review code/workflow changes before integration. Tests/fixtures/reports/CI remain outside the package. This dataset does not prove all-product coverage; BM3 layout and BM4 model evaluation are separate contracts.

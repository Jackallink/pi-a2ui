# v0.1.11: skill-first authoring guidance

`a2ui_render` now directs the model through the installed pi-a2ui skill before composing new Express: read the skill (unless its body is already in context), start from a matching example, adapt it, run helper `check` on the final source and pass the returned arguments unchanged. When skill reading or helper execution is unavailable, the model explains the limitation in prose instead of claiming a preflight ran. The skill adds the complete three-field `FormValidation` example with concrete value semantics: `buttons` is a list of reachable Button ID strings, `rules.fieldId` names the input component rather than its value path, and guarded Buttons/inputs/validator live in the root tree. An orphan-reference repair walkthrough shows the invalid inline-Button form and its fix. When shell redirection or `mktemp` is restricted, use an allowed write/edit tool to create a new owned source file and run the helper check separately; sandbox restrictions and existing project files stay intact.

Schemas, compiler/session/event guards, browser-opening policy, ownership, resource limits, permissions, components and skill templates are otherwise unchanged. Only the shipped description/skill texts and built `dist/assistant-cli.mjs` change. No model request is needed for release validation, and no real-v2 benchmark was run. The original real GLM v1 baseline stays frozen.

## Installation

Requires **Node24.x** and Pi>=1.5.0. Distribution is Git/local, not npm. In a project with no other active registration of this package:

```sh
nvm use 24
pi install -l --approve git:github.com/Jackallink/pi-a2ui@v0.1.11
```

`-l` is project-local. For an existing global registration, update it globally by omitting `-l`; do not add a second registration. Package extension and skill discovery follow the same scope. Restart Pi under Node24 after an upgrade, then use `/a2ui-status` and `/skill:pi-a2ui`. Ready assets are included; consumers do not build TypeScript or browser code.

# v0.1.6 — skill/CLI authoring reliability

Node **24.x only** (`nvm use 24`), Pi>=1.5.0. Git/local distribution only; no npm publication. Install from the Pi project where you want the package enabled:

```sh
nvm use 24
pi install -l --approve git:github.com/Jackallink/pi-a2ui@v0.1.6
```

`-l` is project scope; omit it deliberately for a user-wide installation. `--approve` trusts the selected project for this command. Inspect `pi list` and remove an obsolete Git/local registration in its original scope before switching; loading both can duplicate tools. Tags stay pinned: selecting a new ref is required to upgrade. Package discovery loads its declared extension and pi-a2ui skill together; `/reload` refreshes the selected package, not an older tag. No separate global skill/CLI installation is needed.

For a downloaded archive or local checkout, install production dependencies first, then register its absolute path from the intended Pi project:

```sh
nvm use 24
npm install --prefix /absolute/path/to/pi-a2ui --omit=dev --ignore-scripts --legacy-peer-deps
pi install -l --approve /absolute/path/to/pi-a2ui
```

Ready browser/helper assets ship in Git and the archive. A production consumer needs no TypeScript/tsx/esbuild or browser build. The existing32types,19templates and8pattern routes are unchanged.

# v0.1.10: clearer model-side render triggers

`a2ui_render` now names useful situations: structured multi-field input, review/validation/benchmark results, diffs, charts, tables, comparisons and supported local artifacts. It recommends a canvas when inspection or interaction materially helps the user's next action and skips prose-only answers and trivial confirmations. Actual model-selection improvement has not been measured.

The v0.1.9 native run-summary card is a separate automatic path and remains unchanged. Schemas, compiler/session/event guards, browser-opening policy, ownership, resource limits, permissions, components and skill templates are unchanged. The description grows by362 UTF-8 bytes; this is not a zero-token or cost-saving claim. No model request is needed for release validation, and no real-v2 benchmark was run. The original real GLM v1 baseline stays frozen.

## Installation

Requires **Node24.x** and Pi>=1.5.0. Distribution is Git/local, not npm. In a project with no other active registration of this package:

```sh
nvm use 24
pi install -l --approve git:github.com/Jackallink/pi-a2ui@v0.1.10
```

`-l` is project-local. For an existing global registration, update it globally by omitting `-l`; do not add a second registration. Package extension and skill discovery follow the same scope. Restart Pi under Node24 after an upgrade, then use `/a2ui-status` and `/skill:pi-a2ui`. Ready assets are included; consumers do not build TypeScript or browser code.
